# 进程分流规则：进程名与路径并存、按进程名阻断、取消全局「退出 Routa 后」（设计）

## 1. 为什么做

现在一条进程分流规则只能整体选「按进程名」或「按完整路径」（`match_full_path`），并且只有按完整路径的规则能选「组件故障时：阻断」。另有一个全局设置「退出 Routa 后」管另一批场景。这带来四个问题：

1. **商店应用、自更新应用**（Codex、Claude 等）的路径带版本号，按路径匹配一更新就失效；按进程名匹配又不能阻断。
2. **同名程序**（Chrome 与 Chrome Canary 都叫 `chrome.exe`）不能分别走不同规则。
3. 用户必须在「覆盖所有位置」和「故障时能阻断」之间二选一。
4. 全局「退出 Routa 后」和规则的「组件故障时」交叉管不同场景，难懂；而且全局阻断只靠 ProxyBridge 执行，分流服务停止时悄悄失效。

目标：一条规则同时做到按进程名覆盖所有位置和版本、在 Routa 或组件不可用时阻断，并在分流服务停止时尽量不泄露流量；所有不可用场景只由规则自己的一个选项决定。这次只做进程分流，AI 应用不在范围内（见第 9 节）。

## 2. 目标、非目标、反目标

**目标**
- 规则里每个进程条目带显式类型（进程名 / 路径），同一个程序可以两种都有。
- 按进程名的条目也能阻断。
- 按进程名阻断时，自动记录程序的实际位置，分流服务停止后由系统防火墙（WFP）按这些位置继续阻断。
- 路径优先：别的规则用路径指定的位置，优先归那条规则。
- 取消全局「退出 Routa 后」，规则选项改名「Routa 或组件不可用时」并管所有不可用场景。
- 用户清楚地知道：哪些位置被记录了、哪些位置因属于其他规则而不受阻断、什么情况下仍可能漏、退出 Routa 会让哪些程序断网。

**非目标**
- 不写内核驱动。WFP 只能按完整路径识别程序（2026-11-07 实验已验证：`ALE_APP_ID` 的 `FWP_MATCH_PREFIX` 是"程序路径是条件值的前缀"，不能按目录前缀覆盖新版本；见 `spike/wfp-gap`）。因此"分流服务停止 + 从未记录过的位置首次联网"这个缺口无法完全堵住，只做收窄和提示。
- 不做按商店包身份（`ALE_PACKAGE_ID`）阻断。
- **不兼容旧数据、不考虑老用户迁移**（见 6.2）。
- 不去掉 ProxyBridge 的 32 个代理配置上限（另有独立任务）。

**反目标（做到了也算失败）**
- 自动记录的位置让本该走别的规则的程序被阻断（越界）。
- 记录位置导致已有连接断开或规则闪断。
- 界面多出大段常驻说明（违反 AGENTS.md「减少常驻说明」）。
- 旧配置让整个配置文件被隔离（订阅、节点一起丢失）。

## 3. 用户看到的样子（以原型为准）

### 3.1 规则对话框字段（自上而下）

1. **规则名称**（可选）：不填时显示第一个程序名；多个程序时为「a.exe 等 N 个」。
2. **进程**：一个程序（按文件名）一个标签。
   - 输入进程名回车，按名称添加；粘贴完整路径回车，按路径添加（含 `\` `/` `:` 的预选为路径）；从「正在运行的程序」下拉里选，默认按名称添加，名称被其他规则占用时自动改为按该路径添加并说明原因。
   - 点标签弹出多选菜单：「所有位置（按进程名）」+「指定位置（按路径）」下列出本机正在运行的同名程序位置和已添加的路径，可同时勾选；至少保留一项；底部「删除」移除整个程序。
   - 标签文字：只有名称 `chrome.exe`；名称+路径 `📁 chrome.exe + 1 个位置`；只有路径 `📁 chrome.exe`，多个路径 `📁 chrome.exe · 2 个位置`。悬停显示全部条目。
   - 「所有位置」下的说明：若其他启用规则用路径指定了同名程序的某些位置，写「其中「X」指定的位置走那条规则」。被占用的路径禁用并写明属于哪条规则。
   - ? 说明（逐字）：`所有位置（按进程名）：同名程序装在哪里都会命中。／指定位置（按路径）：只命中这个位置的程序。／同一个程序可以两个都选。／同名程序：填了路径的规则优先。`
3. **节点**：节点选择窗口（与现有一致，含延迟）。
4. **网卡**：系统默认或指定网卡；Tailscale 节点时锁定并提示在节点设置里改。
5. **启用**：开关，新建默认打开。
6. **Routa 或组件不可用时**：直连 / 阻断，**新规则默认直连**。说明放进 ?（见 3.3）。
   - 选阻断且某程序在其他启用规则里有路径指定的位置时，下方一行：「chrome.exe 在「Chrome Canary」指定的位置不受这条规则阻断。」
   - 编辑已有规则且为阻断时，下方显示「已记录的位置」折叠行（见 3.2）。
7. **规则变化时断开旧连接**：开关，说明放进 ?（`仅对 IPv4 TCP 连接有效；换节点、停用或删除规则时也会断开。`；2026-11-10 起更换代理目标也会断开，原文为“更换代理目标不触发断开。”，见 AI 应用设计 3.10）。

### 3.2 已记录的位置

仅当规则为阻断、且至少有一个按进程名的程序时显示。在规则列表卡片里和对话框「Routa 或组件不可用时」下方各有一处，默认折叠：
- 折叠行：「已记录 N 个位置」；有被跳过的位置时追加「，M 个位置属于其他规则」；N=0 时显示警告色「尚未记录位置」。
- 展开后：每个记录的路径一行（等宽字体），不在运行的标「未运行」，每行可单独移除（按钮 tooltip「移除这个位置（程序再次联网时会重新记录）」）。N=0 时说明「程序联网后自动记录。在此之前，分流服务停止时拦不住。」被跳过的位置灰色显示，注明「不记录：这个位置属于规则「X」，不受这条规则阻断」。
- 记录由系统维护，用户不能手动添加（要固定某个位置，就把它作为路径条目加入进程）。

### 3.3 提示文案

- 「Routa 或组件不可用时」的 ?（逐字）：`Routa 退出或尚未运行、mihomo 内核启动或被停止、内核或分流组件出故障时生效；节点失效、网卡断开时，始终阻断。／选阻断后，按进程名匹配的程序也会被阻断。程序联网时会自动记录它的位置，分流服务停止后，系统防火墙按这些位置继续阻断；还没联网过的位置除外。／其他规则用路径指定的位置不会被记录，也不会被这条规则阻断。`
- **toast**：保存后，若这次保存让某些程序**新进入**"按进程名阻断"（新建进程名规则并选阻断、直连改为阻断、或在已阻断的规则里新增进程名），弹一次信息 toast（约 10 秒，可关闭）：「已开启按进程名阻断／X、Y 联网时会自动记录位置，分流服务停止后也能拦住；还没联网过的位置除外。」若有被跳过的位置，追加「「Chrome Canary」指定的 chrome.exe 不受影响。」只改节点、名称等的保存照旧显示简短成功提示。学到新位置时**不**弹提示。
- 规则列表卡片：左侧启用开关；停用时整卡变淡、标题旁「已停用」；启用且阻断时标题旁「不可用时阻断」。

### 3.4 停用进程分流与退出

- **托盘菜单**新增两项（进程分流开着且有启用规则时显示）：「停用进程分流」「停用进程分流并退出」。进程分流关着时第一项显示为「启用进程分流」，第二项不显示。
- **进程分流页**：已有总开关即「停用进程分流」；在其旁边增加按钮「停用并退出」。
- **退出提示**：用户点托盘「退出」时，若进程分流开着、且有启用的阻断规则，且用户没选过「不再提示」，先打开主窗口并弹对话框：
  - 标题：「退出 Routa？」
  - 正文：「下面这些规则选了阻断，退出后对应程序会断网，直到 Routa 再次运行：{规则名，以、连接}」
  - 按钮：「停用进程分流并退出」「仍然退出」「取消」；复选框「不再提示」。
- 设置页「进程分流」里原来的「退出 Routa 后」选项删除。

## 4. 行为规则

### 4.1 进程条目与匹配

- 每个条目带显式类型 `{ kind: Name | Path, value }`，保存后以 `kind` 为准，不从内容推断。校验要求两者一致：`Name` 的值不能带目录，`Path` 的值必须是完整路径。
- 规则内：同一进程名不能出现两次；同一路径不能出现两次；同名的进程名和路径可以并存。
- 规则间冲突：进程名与进程名（同文件名）冲突；同一路径冲突；进程名与另一条规则的路径**不冲突**。判重包含停用规则。
- **路径优先**：一个程序同时命中 A 规则的进程名和 B 规则的路径时，走 B。实现上路径规则排在 ProxyBridge 规则表最前。
- **停用的规则**：「被其他规则占用的位置」只看启用的规则（且全局开关打开），与运行时一致。规则启用 / 停用时，其他规则的守护与跳过随之重新计算。
- Routa 自身、内置 / 自定义 mihomo 内核的禁用检查：`Name` 比较文件名，`Path` 比较整条路径。

### 4.2 「Routa 或组件不可用时」

**原则：进程名 + 阻断与路径 + 阻断处理完全相同**，唯一区别是进程名条目受 WFP 守护的路径是动态的（自动记录或商店更新事件得来）。所有不可用场景都按规则自己的选项：

| 场景 | 处理 | 路径条目 | 进程名条目 |
|---|---|---|---|
| 内核崩溃、恢复中 | 按规则选项 | ProxyBridge 执行 | ProxyBridge 按名称执行 |
| 内核正常启动中、被用户手动停止 | 按规则选项（原为全局） | 同上 | 同上 |
| Routa 崩溃、正常退出、开机后尚未连上 | 按规则选项（正常退出 / 尚未连上原为全局） | 服务回落执行 | 服务回落执行 |
| 分流服务停止 / 崩溃 / 开机尚未启动 | 选阻断的规则 | WFP 永久阻断 | 已记录的位置 WFP 阻断；未记录的位置直连 |
| 卸载分流服务 | 不阻断（同现在：卸载清掉全部 WFP 规则） | — | — |
| 未选节点、节点失效、新配置无法生效导致内核被防泄露停止、内核非用户原因未运行 | 固定阻断（不变） | — | — |
| 其他规则用路径指定的位置 | 不受本规则影响 | — | — |

### 4.3 自动记录位置

- **谁需要记录**：启用的、阻断的规则中的每个进程名条目。
- **来源**：
  1. **分流服务从连接里学**：服务注册 ProxyBridge 连接回调（回调给出文件名和 PID，每个新进程的第一次连接都会触发），按 PID 取完整路径；命中时立即加入 WFP 守护、持久化，并经 `GetStatus` 回报 Routa，Routa 存进模型 `learned`。Routa 不在时服务照样学。
  2. **商店应用安装 / 更新事件**：只能在用户会话里收到，由 Routa 用 `PackageCatalog` 监听；新版本装好、尚未启动就推导出新路径。
  3. **保存规则时**：Routa 立即记录本机正在运行的同名程序位置（只对本次新进入学习的进程名）。
- **不记录**：属于其他启用规则路径条目的位置；本规则自己的路径条目；Routa 与内核本身。
- **清除**：规则改为直连、停用、删除，或删掉对应的进程名条目时，该程序的记录及其 WFP 阻断一起清除；文件已不存在的记录自动删除；用户可逐条移除。
- **不断连**：新增记录只新增 WFP 永久阻断 + 动态放行，不改动 ProxyBridge 规则，不触发「规则变化时断开旧连接」。
- 「设置 → 清理残留阻断规则」能清掉这些 WFP 规则（现有机制按 provider 清理）。
- **不设软件自定义上限**：记录与守护路径数量不限，靠删除不存在的文件控制增长。

### 4.4 缺口收窄

- 分流服务已设为自动启动、故障后 1 / 5 / 30 秒重启（现有安装逻辑），无需改动。
- 剩余缺口只在"分流服务不在运行时，从未记录过的位置第一次联网"，通过 3.3 的 ? 说明、toast 和「尚未记录位置」告知用户。

## 5. 取消全局「退出 Routa 后」

- 删除 `ProcessRouting.on_routa_exit`、`ExitPolicy`、`DesiredState.on_routa_exit`、设置页的选项及相关测试。`save_process_routing_settings` 只保留 `enabled`。
- Routa 端 `decide.rs`：内核正常启动中、被用户手动停止 → 按规则 `on_fault`。
- 服务端 `fallback.rs`：Routa 正常退出、开机后尚未连上 → 按规则 `on_fault`（与 Routa 崩溃相同）。
- 规则选项字段名 `on_fault` 不变，界面名改为「Routa 或组件不可用时」；**新规则默认直连**（不变）。
- **不做老用户迁移**：升级后规则保持各自的选项，原全局设置直接丢弃。
- 失去的能力：同一条规则「崩溃时阻断、主动退出 Routa 时直连」。替代：「停用进程分流并退出」（3.4）。

## 6. 数据与协议

### 6.1 数据

- `ProcessRule`：`processes: Vec<ProcessEntry>`，`ProcessEntry = { kind: ProcessKind, value: String }`，`ProcessKind = Name | Path`；删除 `match_full_path` 和旧字段 `exe_path`；新增 `learned: Vec<String>`（系统维护，前端只读 + 可移除）；`user_enabled`、`on_fault` 不变。
- `ProcessRouting`：删除 `on_routa_exit`；新增 `exit_prompt: bool`（默认 `true`，用户勾「不再提示」后为 `false`）。

### 6.2 旧数据

- 不做格式转换，也不迁移老用户的设置。
- 唯一的处理：读取配置时，若 `process_routing.rules` 里有旧格式的规则（`processes` 含字符串、或带 `exe_path` / `match_full_path`），**丢弃这些规则**，其余配置照常读取。不能让整个配置文件因此被隔离。旧的 `on_routa_exit` 字段直接忽略。

### 6.3 校验（`validate.rs`）

- 去掉 `ProcessNameCannotBlock`；判重按 4.1；每个条目按自身类型校验。
- 代理配置按代理地址共用：Routa 为每个「节点 + 网卡」组合只建一个隐藏监听端口（`model/hidden.rs`），所以 ProxyBridge 的 32 个代理配置限制的是「启用规则里不同的『节点 + 网卡』组合数」。超限文案：「走代理的「节点 + 网卡」组合最多 32 个」。

### 6.4 协议（`PROTO_VERSION` 4 → 5）

- `RuleSpec` 增加 `kind` 与 `guard_paths`（进程名条目的已知位置，仅用于 WFP 守护）；`DesiredState` 删除 `on_routa_exit`；`SvcStatus` 增加 `learned`（服务自己学到、还不在下发里的位置）。
- 服务端：路径规则排在进程名规则之前；进程名 + 阻断由 ProxyBridge 执行，WFP 守护只装在路径条目和已知位置上；代理地址相同的规则共用一个 ProxyBridge 代理配置；文件不存在的守护路径跳过，不让规则失败。
- 版本不匹配时沿用现有「更新组件」提示。

## 7. 约束

- Windows 防火墙只能按完整路径识别程序（已实验验证）。
- 界面遵循 AGENTS.md：常驻说明最少，辅助说明进 ? 或折叠；对话框固定高度、内容区滚动。
- 文案为中文，风格与现有界面一致。

## 8. 已决定的事项

由用户决定：
- 字段：规则名称、进程（进程名 / 路径）、节点、网卡、启用、组件不可用时（直连 / 阻断）、规则变化时断开旧连接。
- 进程交互用标签 + 点击多选菜单；同一程序允许进程名和路径并存；路径优先。
- 每个进程条目带显式类型字段（`kind`），不从内容推断。
- 按进程名也能阻断，通过学习位置保证分流服务停止时尽量不泄露；处理与路径 + 阻断完全相同。
- 学习：从连接里学放在分流服务里；另加商店应用更新事件。
- 提示：保存时弹 toast；被其他规则占用的位置要在界面上说明。
- 软件自定义上限能去掉就去掉；ProxyBridge 的 32 暂不去掉（另有独立任务）。
- 只做进程分流，不做 AI 应用；在当前 worktree 分支上做。
- 取消全局「退出 Routa 后」，统一按规则选项；新规则默认直连；不考虑老用户迁移；不兼容旧数据，但旧格式的分流规则只丢掉规则本身。

由设计者决定（可推翻）：
- 规则选项改名「Routa 或组件不可用时」；托盘与进程分流页的「停用进程分流（并退出）」入口；退出提示的触发条件与文案、「不再提示」存在 `ProcessRouting.exit_prompt`。
- 添加进程时按内容预选类型。
- 已记录的位置存进模型 `learned`，界面只读可移除，不显示成进程标签。
- 保存时预先记录正在运行的位置；学到新位置不弹 toast。
- 跳过的位置在三处说明：对话框选项下方、已记录列表、保存 toast。
- 判断"被占用"只看启用规则。
- 卸载分流服务时清掉全部阻断（同现在）。
