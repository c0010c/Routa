# Routa 紧凑节点卡片 V1

本轮交付设计预览，等待用户评审。没有修改正式业务源码、运行配置或既有设计目录。

打开 `index.html` 即可浏览四个画板，也可以通过本轮本地预览服务访问。画板为 1440 × 900 CSS px；设计页的导航条位于画板外。所有示例节点、来源、时间与延迟均为演示数据，不读取真实订阅或凭据。PNG 是 Chrome 中该设计稿的实际渲染，不是当前正式应用截图。“当前卡片”按最新 `NodeCard.tsx` 的尺寸与信息顺序复刻。

名称优先占宽，保留两行；更多操作始终位于右上角且可见。超出两行省略，悬停或键盘聚焦显示完整名称。协议与来源不挤占延迟行；延迟数字使用等宽数字。没有为了压缩卡片把辅助文字缩小到 10 px。

页面保持原有 184 px 侧栏和 24 px 内容边距，分组容器使用 12 px 内边距。页面列表内部滚动。四列、640 px 纯卡片区域的示例容量从 4 行 16 张提升为 6 行 24 张，即增加 50%；实际容量取决于窗口、分组标题和展开状态。

弹窗的标题、搜索工具栏、68 px 底部操作固定，中间列表滚动。搜索无结果、筛选、测量和滚动不会改变弹窗高度。小屏正式实现应保留 `max-height: calc(100dvh - 40px)`，并让内容区收缩、内部滚动；960 px 是此次桌面画板的示例宽度，不应成为最小窗口宽度。

## 延迟与状态规则

三处共用同一个映射，不因页面或选中状态改变颜色：

| 结果 | 颜色 | 展示 |
| --- | --- | --- |
| ≤150 ms | `#0f7b0f` | 数值 + ms |
| 151–300 ms | `#5f7a18` | 数值 + ms |
| 301–600 ms | `#9d5d00` | 数值 + ms |
| >600 ms | `#c42b1c` | 数值 + ms |
| 超时 | `#c42b1c` | 超时；提示说明测试超时 |
| 连接失败 | `#c42b1c` | 连接失败；提示说明连接、解析或握手失败 |
| 未测试 | `#616161` | 未测试 |
| 正在测量 | 中性色 | 测量中…；不可按 0 ms 处理 |
| 内核未运行 / 无响应、节点未生效 | 共用原因映射 | 保留具体原因，不全部改写成超时 |

沿用现有节点卡片的 150 / 300 / 600 ms 分界。第二档绿色由当前主题的 `#66851c` 稍微加深，保证在白底及选中浅蓝底上的小字对比度。高延迟、失败和未测试均有文字或明确数值，颜色不是唯一线索。

统一文案：`测速` → `测延迟`，`测速中…` → `测量中…`，`未测速` → `未测试`，`有效节点` → `候选节点`。自动策略名称若后续一并调整，建议使用 `自动选低延迟`，避免“测速”暗示带宽测试。本轮不修改正式策略文案。

节点页与切换弹窗使用“节点延迟”；代理卡片标为“当前代理延迟”。对象、测量完成时间、测试地址和网卡路径放入悬停/聚焦提示，不增加常驻解释。节点卡片所处页面已说明对象，因此不在每张卡片重复常驻“节点延迟”标签。

## 当前实现核对结论

1. **颜色差异已确认。** `src/components/NodeCard.tsx` 按 ≤150 / ≤300 / ≤600 / >600 分档。`src/pages/ListenerNodeDialog.tsx` 则把所有 `ms != null` 的结果都用 `success.main`，失败结果用次要文字色，因此同一个 437 ms 在两处会出现橙色/绿色差异。`src/lib/format.ts` 还存在另一套 200 / 500 ms 的 `delayColor`，后续正式实现也需收敛，避免再出现第三套标准。
2. **节点页与选择器的测量对象一致。** `ResourceCenter.tsx` 用 `${订阅名}/${节点名}` 或 `手动/${节点名}` 作为查询键；`ListenerNodeDialog.tsx` 通过 `proxyNameOf` 生成相同键。两者都从 `useStatus()` 的 `["status"]` 查询读取 `delays`，并调用同一个 `useTestDelays()`。没有看到各自保存独立延迟缓存的逻辑。
3. **代理卡片的对象不同。** `Listeners.tsx` 读取 `s.delays[target.name]`，点击测量时传入 `[target.name]`；这里是出口名称。节点页和弹窗传入原始节点的代理名称。
4. **测试路径可能不同。** `src-tauri/src/config_gen/mod.rs` 为基础节点生成不额外绑定出口网卡的条目，出口则复制节点或构造策略组，并可写入出口的 `interface-name`。同名显示节点不代表同一个 mihomo 测试对象或同一出站路径。代理卡片的值是出口测试结果，不能称为本地代理端口的端到端延迟。
5. **时间和结果保留是差异来源。** `src-tauri/src/stats/delay.rs` 为每个结果保存 `tested_at`；`runtime/mod.rs` 将测试结果按传入名称写入 `DelayBook` 并发布状态。节点与出口分别记录、可在不同时间测量。当前没有基于时间自动过期的显示逻辑；无内核运行时测试还会保留旧 DelayBook。选择或配置路径改变后，不能直接把旧出口结果当作新路径的当前结果。
6. **无法回溯认定 170 / 487 ms 数值错误。** 本次没有该次测量的对象、完成时间、网卡路径和运行状态快照，也未发现当前打开的 Routa 原生窗口。已检查 Chrome 的“Agent专用”连接中旧 V4.3 预览，其节点页仍是表格，属于旧设计样本，不作为最新正式卡片实现的证明。本轮以最新源文件为准制作对照。

后续正式实现建议：共用 `DelayIndicator` 和卡片信息结构；基础节点使用同一稳定对象键和状态缓存；出口结果附上测量时的出口配置/成员指纹，切换节点或网卡后标记 `待重测`，旧值仅留在提示中；成功测试后以对应的新结果替换。`tested_at` 本身不足以证明旧结果对应当前路径，因此这项需要正式实现时补充状态关联，不能仅靠改标签解决。

## 状态与动效

- 悬停：120 ms 背景、边框、轻阴影变化，卡片不位移、不缩放。
- 选择：蓝色 2 px 内描边、浅蓝底和勾选标识；保留节点延迟的原有状态颜色。当前实际使用的节点另有“当前使用”，新选节点标为“待切换”，两者不混淆。
- 更多操作：独立于选择操作，始终有 26 × 26 px 的桌面点击区域；右键、键盘菜单和焦点行为在正式实现中沿用现有能力。
- 无结果及加载：保留弹窗高度和固定操作区，不因内容减少而重排外框。
- `prefers-reduced-motion` 时关闭过渡。

## 交互边界

设计稿可以切换画板、搜索、选择候选节点、演示测延迟、展开/折叠分组、排序、查看悬停提示及更多菜单。所有操作只作用于本地演示状态，不调用 mihomo，不创建真实代理，不写入正式配置。代理卡片只用于展示当前代理延迟命名和切换入口，不扩展本轮范围。
