Routa · 完整 UI 与交互规范

v1 · 2026-10-29 · 亮色版 · 简洁版与完整版统一设计

目标：普通用户无需理解监听器与出口即可开始代理；需要精细控制时，切换完整版继续使用同一份配置。设计原型只使用示例数据，不访问订阅链接、不修改 Windows 设置、不安装组件。

1. 界面结构

模式主要入口用途
简洁版连接；底部订阅与节点、设置选择节点、开启代理、按需代理指定应用
完整版概览 → 代理 → 进程分流 → 出口 → 订阅与节点；设置固定底部管理多监听器、多出口、应用规则与高级设置
资源子页订阅 / 手动节点 / TailscaleTailscale 归入节点资源，不新增左侧主菜单

图标沿用确认的 A 组：概览 SpaceDashboardOutlined，代理 SwapHorizOutlined，进程分流 AltRouteOutlined，出口 LanguageOutlined，订阅与节点 DnsOutlined，设置 SettingsOutlined。

2. 首次启动与模式切换

首次启动→简洁版 / 完整版→导入订阅或手动节点→选择节点→主动开启代理
  • 只有尚未选择过界面模式的全新用户看到模式选择。默认选中简洁版，允许直接选择完整版。
  • 保存界面模式到本机偏好。不能用“没有订阅”判断首次启动，清空订阅也不能再次触发模式选择。
  • 升级的既有用户保留完整版及已有配置，避免升级后突然改变操作位置。
  • 设置 → 界面模式即时切换。切换不重启内核，不关闭监听器，不重写出口或规则。切换过程中如有未保存编辑，先选择继续编辑或放弃修改。
  • 界面模式不等于代理模式。不要把“简洁版”当成系统代理、TUN 或分流策略。

3. 简洁版的默认配置

全新安装默认有一个受简洁界面管理的监听器：127.0.0.1:7881，混合协议 HTTP + SOCKS5。首页隐藏监听器、出口与网卡术语。导入并选择节点后，程序维护对应默认出口与关联关系。

  • 首次进入无节点：显示导入订阅为主操作，手动添加为次操作。导入成功不自动开启代理。
  • 端口 7881 被占用：不静默改端口，不显示连接成功。提示占用并提供更换端口入口，建议一个空闲端口。
  • 从完整版返回：只操作被标记为“默认代理”的那一组对象。不能根据数组第一项、名称或端口猜测管理对象。
  • 默认代理对象被删除或无法识别时，要求用户选择绑定或显式创建；不覆盖既有监听器。其他任务仍在运行时，在简洁版就近提示并链接完整版。
  • 关闭简洁版代理只释放默认代理的接管，不停止其他监听器和其他用途的规则。

4. 连接操作与状态

状态界面允许操作下一步
无节点添加节点后即可开始导入订阅 / 手动添加获得节点后待连接
待连接灰色状态；开启代理按钮选节点、调整范围、开启代理应用中
应用中正在应用…；相关控件禁用只可浏览其他页面；不能重复提交已开启或失败
已开启绿色状态；关闭代理；速度数据切换节点、关闭代理、管理应用切换中 / 待连接
连接失败就近错误与重试、更换节点、诊断保留节点与输入，允许修复重试后按真实结果更新
节点切换失败原节点仍使用；错误保持可见重试选择或取消原连接不受错误覆盖
状态未知正在确认代理状态；不能显示成功刷新运行状态、打开诊断以后端运行结果为准

“代理已开启”表示相关接管已经应用成功，不承诺外网永远可达。节点超时与代理配置已启用是两个状态。没有流量时显示 0 B/s，未开启或数据不可用时显示 —。不使用装饰性的信号强度代表连接质量。

开启顺序：验证节点与端口 → 启动必要运行组件 → 应用默认出口与监听器 → 应用接管方式 → 读取实际运行状态 → 更新成功界面。失败时清理本次新增接管、恢复此前可确认的状态，不能留下“按钮成功但系统未应用”。超时先重新查询实际状态，再允许重试，避免重复操作。

5. 系统代理、TUN 与指定应用

  • 简洁版只有一个当前接管范围。系统代理 / TUN / 指定应用相互切换时，先检查冲突，再应用新方式，成功后撤销旧方式；失败恢复原方式。
  • 系统代理只影响遵循 Windows 系统代理设置的应用。界面不使用“所有应用都代理”的保证性文案。
  • TUN 放在连接选项中。首次启用时解释虚拟网卡与管理员权限，并显示当前是否生效。
  • 指定应用：共用当前节点与默认监听器；选中应用代理，未选中应用直连。前提是本次接管中已释放系统代理与 TUN；若存在其他外部代理，显示实际可确认状态，不作全局直连保证。
  • 首次使用应用分流时才引导安装组件。明确需要管理员权限，允许暂不启用；拒绝授权与安装失败不能修改用户原有连接方式。
  • 应用开关先显示应用中，生效后更新；失败回到原开关状态并说明原因。关闭/移除规则与意外故障是不同操作。
  • 意外故障默认阻断选中应用，允许明确改为直连。节点失效或网卡消失按现有项目行为阻断受影响应用；主动退出按全局退出策略执行。

进程分流：行内切换监听器

  • 每条进程规则的监听器列使用下拉框，显示“端口 · 名称”。选择后自动应用，无需先进入编辑弹窗。
  • 只列出支持进程分流的混合或 SOCKS5 监听器；已停用的监听器标注并禁止作为新目标。失效的当前引用显示“监听器不可用”，不擅自替换。
  • 每行独立应用：该行显示“正在应用…”并禁用重复切换；其他行仍可操作。应用成功后更新关联，失败恢复原监听器并在行内提供重试。
  • 修改未启用规则的监听器只保存目标，不自动启用规则。修改一条规则不会改变其他进程的目标。
  • 后续新连接使用新监听器，不默认强制断开已有连接。相关说明放在监听器列标题的 ⓘ 中。
  • 下拉末项提供“＋ 新建监听器…”。从此入口创建后，自动关联到当前进程；取消时保留原目标。编辑表单与行内选择共享同一监听器 ID。

表单原则

  • 基础字段先展示，监听地址、认证、绑定网卡、故障策略等按需展开。风险提示只在相关设置启用时出现。
  • 监听器：名称、端口 1–65535、混合/HTTP/SOCKS5、出口。端口避免与控制端口、其他监听器重复，保存后读取后端最终生效结果。
  • 进程规则必须指向可用于分流的混合/SOCKS5 监听器；不提供 HTTP-only 监听器选项。按完整程序路径去重。
  • 出口策略组至少一个成员；四种策略为自动测速、故障转移、负载均衡、手动选择。网卡与 Tailscale 绑定冲突就近处理。
  • 保存中禁用重复提交及关闭操作。失败保留全部输入；关闭有未保存修改的表单时提供继续编辑 / 放弃修改。
  • “保存到磁盘”和“运行时已生效”分别反馈；持久化失败、热加载拒绝不能统一显示为成功。

9. 无障碍与操作细节

  • 完整键盘路径：Tab / Shift+Tab；空格切换开关；Enter 提交；Escape 关闭无未保存修改的弹窗。
  • 弹窗焦点限制在弹窗内，关闭后回到触发控件；保存中不会因 Escape 误关。
  • 重要错误常驻到修复；成功反馈可短暂消失；异步状态使用 aria-live，不抢占输入焦点。
  • 恢复焦点、关闭表单、页面切换均不能清空尚未提交输入。尊重减少动画设置。
  • 长节点名与长程序路径：单行省略并可查看完整内容；不要把关键状态挤出窗口。

10. 能力边界与实施顺序

能力当前代码情况实施要求
节点 / 订阅 / 出口 / 监听器已有模型、表单与后端调用复用业务能力，重组信息层级，统一运行反馈
进程分流已有组件安装、规则和状态接口简洁模式映射默认监听器与受管理应用规则；保留现有故障语义
简洁版与首次启动待实现保存 UI 偏好、稳定管理对象标识、升级与异常迁移
系统代理与 TUN 控制现有 UI / bindings 尚无对应控制接口先补后端接管、权限、回滚、退出恢复与真实运行状态，再接界面
启动自动连接 / 托盘关闭偏好本轮设计新增持久化并处理无节点、登录启动、异常恢复；不得覆盖别的程序刚设置的系统代理

顺序建议：① 导航 A 组与亮色组件统一；② UI 模式偏好、首次启动及配置映射；③ 简洁版节点与订阅闭环；④ 系统代理控制与可恢复状态机；⑤ 指定应用简化；⑥ TUN 权限与回滚；⑦ 所有错误、迁移与无障碍验收。

11. 设计验收清单

  1. 新用户能完成模式选择 → 导入 → 选节点 → 手动连接 → 关闭代理。
  2. 简洁版能选择应用、处理安装授权、看到应用规则应用失败并保留原状态。
  3. 切换简洁版 / 完整版不丢配置、不停止其他监听器。
  4. 完整版六个入口及主要新增、编辑、删除流程完整可达。
  5. 覆盖空列表、加载、校验、忙碌、断网、权限拒绝、端口冲突、引用删除和配置应用失败。
  6. 离线设计原型不发起真实订阅请求、不操作 Windows 代理、不写业务配置。

原型覆盖代表性主流程与状态；系统对话框、Tailscale 外部登录、组件安装与运行数据均为模拟。实施时以后端实际结果驱动 UI，不能把演示定时器用于生产逻辑。
